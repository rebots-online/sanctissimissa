## 2. Architecture verdict — invariants HOLD

- **Collinear rule: HOLDS.** `src/core/data/loadCorpus.ts` is the sole platform branch (`__TAURI_INTERNALS__` sniff → `invoke('load_corpus')` vs web `fetch('/missal.db')`). Zero `import.meta.env` in `src/`; the only `fetch` in the app is that one line; no XHR/WebSocket/EventSource. The accompaniment sidecar's Tauri/IndexedDB branch is the user-data byte-persistence mirror sanctioned by ARCHITECTURE §7.6.
- **Layering: CLEAN.** No `src/ui` → `scripts/` or node-builtins; no `src/core` → `src/ui`.
- **SQL: uniformly parameterized.** Every query in `corpusDb.ts`, `store.ts`, `scripts/*.mjs` binds with `?`; FTS5 MATCH grammar neutralized by `normalizeText` reducing input to `[a-z ]` before quoting. No SQL injection surface.
- **Tauri surface: minimal.** 3 commands (`load_corpus` serves `include_bytes!`-embedded static DB — zero input-derived paths; `save_sidecar` writes a fixed `app_data_dir/sidecar.db`); `capabilities/default.json` = `core:default` scoped to window `main`; no fs/shell/http plugins; no `withGlobalTauri`; Android release has `usesCleartextTraffic=false`, INTERNET-only permission, non-exported FileProvider, R8 minified.

This is a well-disciplined codebase. The findings below are about what the discipline hasn't reached yet — chiefly hot-path cost and failure-surfacing.

### 4.2 CSP impact analysis — why the obvious fix is the dangerous one
- **On web, a Tauri-style policy is compatible and beneficial:** `index.html` has zero inline scripts; all assets same-origin; sql.js needs `'wasm-unsafe-eval'`; React inline styles need `style-src 'unsafe-inline'`. The print window from `window.open()` inherits the opener's CSP, so a CSP genuinely backstops M1.
- **But the naive meta tag can kill the native builds:** `index.html` ships inside the Tauri webview too. Browsers enforce header CSP **and** meta CSP, taking the intersection — and Tauri authorizes its injected init script via nonces in the *header* CSP, which a static meta cannot know. Result if too strict: `__TAURI_INTERNALS__` blocked → corpus load falls back to `fetch('/missal.db')` → fails in the webview → **blank app on desktop/Android**.
- **iframe-embeddability is a product requirement** (sanctissimissa.com and other sites/apps). Consequences: (a) **`netlify.toml`'s `X-Frame-Options: DENY` conflicts with this direction** and should not survive to any host that serves the app — the live nginx vhost (verified) sends no framing headers, so the app is embeddable today; (b) `frame-ancestors` (the allow-list mechanism that blocks clickjacking while permitting chosen embedders) is **ignored inside meta CSP** — header-only — so the eventual partner allow-list must ride the response-header route; (c) **storage partitioning**: IndexedDB/localStorage in a cross-origin iframe are partitioned per top-level site in modern browsers — annotations created inside an embedded instance would live in a separate partition from the standalone site unless the planned sidecar sync (PEER-SIDECAR-SYNC) or the Storage Access API bridges it. Design the sync plane with this in mind.
- **Safe implementation shape, when authorized:** inject the CSP only into the **web PWA zip's `index.html` at collect-artifacts time** — build-side bytes, zero server writes, native untouched, honoring the push/pull-no-server-writes contract.

### 4.3 Release manifests & the automanifest mount — diagnosis
Intent (operator): manifests are deterministic build outputs that auto-populate on every successful build; the server side only pushes/pulls — never writes code or config. Verified: `dist/manifest.json` (rolling) and `dist/release-manifest-v<version>.{json,xml}` (version-pinned) share schema `mba.robin.release-manifest.v1`, are generated with hashes of the actually-staged files, and self-report missing changelog sections. **Diagnosis of the blocked "standroid.robin.mba automanifest mount":**
1. **The deploy step was never run for v1.31.66058** — the manual zip→ssh→tar→symlink-swap procedure (Admin-Manual "Deploy procedure") was not executed; live root `Last-Modified` is 2026-08-02, Admin-Manual's last *verified* release is v1.18.35665 (2026-07-15).
2. **The manifest isn't in the web payload**: `curl https://standroid.robin.mba/manifest.json` returns the SPA's `index.html`, not JSON — the release manifest never rides in the PWA zip, so nginx's `try_files … /index.html` fallback swallows the path. The vhost needs no changes; the bytes are simply absent.
**Recommendation (when authorized):** include the release manifest in the web PWA zip at collect time — the server then serves it as ordinary static bytes through the existing config, auto-populating per successful build with zero server-side writes.
