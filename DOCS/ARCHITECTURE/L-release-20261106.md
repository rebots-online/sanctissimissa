- `stageRunsOnHost(stage, platform)` returns `STAGE_ENVS[stage].includes(envOf(platform))`.

## 3. Flows

**F1 — Pre-release content inputs (once per corpus version; ubuntu; not a release stage).**
1. `npm run corpus:pipeline` creates `.tmp/corpus-build/<corpus_version>/`. The `corpus_version` is
   `corpus-<UTC YYYY.MM.DD-HHMM>`.
2. It runs, each with `--out` into that directory:
   1. `ingest` (output path argument, `scripts/ingest-corpus.mjs:40`);
   2. `ingest:commentary`;
   3. `embed:corpus`;
   4. `build:modules`.
   Flags and internals belong to the content-modules partial.
3. `--vendor` copies the new corpus and modules into `VENDORED/` with exclusive create. It writes
   `CURRENT.json` with `previous` set to the old version, and appends PROVENANCE.
4. The author adds the `DOCS/MISSAL-DB-VERSIONS.md` entry `### <corpus_version>` (R5).
5. **First run only.** Vendor the currently shipped corpus first, as
   `sanctissimissa-corpus-2026.09.09-2054.db` (sha256 `7286cd357d43b75132d83aabbf8c64cb0dc7b3c44f6fd1e016729a592a14d2fa`).
   Add its missing retroactive ledger entry. It becomes the new pointer's `previous`, which is the
   rollback target.
6. Embedding needs the embedder in local Ollama. If its blob digest is not the pin, import it offline
   from the vendored GGUF: `ollama create qwen3-embedding:0.6b -f <Modelfile FROM
   VENDORED/models/sha256/06507c7b…/…>`. The blob digest equals the GGUF sha256.
7. Commit (LFS), then push to Forgejo first.

**F2 — Release invocation (ubuntu).**
1. Commit the abandoned 1.69 inventory and the CHANGELOG section (§2.9).
2. Run `npm run build:release -- --restart`. It stamps 1.70.x and commits
   `v1.70.x: stamp complete release [skip ci]` (`:463-476`).
3. It then runs the stages: `inputs` → `web` → `modules-deploy` → `web-deploy` → `linux` → `windows`
   → (skips msi/msix) → `android-release` → `symbols` → `collect`.
4. `collect` runs partial (§3.4) and exits 2, with only `@windows` pairs missing.

**F3 — Windows continuation.** Bootstrap the worktree (§2.3), then run
`npm run build:release -- --resume-only`. The stages run in order:
1. `inputs`
2. `web`
3. `linux` (container)
4. `windows` (native)
5. `windows-msi`
6. `windows-msix`
7. `android-release`
8. `symbols` (container)

Return the produced `dist/*-buildenv-windows.*` files and the windows lock copy to the canonical
checkout's `dist/` (any file copy). Push the LFS objects from the canonical checkout only.

**F4 — Collection and attestation (ubuntu).** `collect-artifacts.mjs --auto` works as follows:
1. If the union of pairs (§2.3) is missing any `REQUIRED_PAIRS` entry other than `collect@ubuntu`,
   it runs partial mode: `PARTIAL` (`:113`), manifest `partial`, incomplete inventory. It does not
   mark `collect@ubuntu` and exits 2.
2. Otherwise it runs strict mode:
   - verifies Android signatures and identity for both env APK/AAB sets (`:300-330`);
   - verifies the RPM identity (§2.8) and the Windows receipts;
   - writes the manifest, XML and notes;
   - marks `collect@ubuntu`.
3. The handback then runs the TEST_RUBRIC gauntlet (§5) on **both** env sets (D12: every artifact
   runs rows 1–10).

**F5 — PWA cutover.** `web-deploy@ubuntu` publishes. Before that, record the live version from
`https://sanctissimissa.surge.sh` in the run report; it is the returning-visitor baseline. Row
L.7-11d is then driven in a browser profile that carries that version's service worker.

**F6 — Rollback (R5; nothing is deleted).**

| What | How |
|---|---|
| Web | `surge sanctissimissa.surge.sh cutover <previous revision>` (runbook §Surge) |
| Corpus or module | Commit a `CURRENT.json` / `modules.json` revision pointing at the retained previous file, then run a new release invocation (an input change ⇒ a new stamp) |
| Runtime host | Files are immutable and stay; old manifest URLs keep resolving |
| Play | Halt the staged rollout in the console |
